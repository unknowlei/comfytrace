# ComfyTrace 项目展示材料

## 简历写法

**ComfyTrace | 离线 ComfyUI 工作流分析工具**

- 设计并实现 UI workflow / API prompt / PNG 元数据的多格式归一化管线，
  以独立 TypeScript 核心支持浏览器交互与 CLI 自动化调用。
- 实现图结构诊断、依赖清单与基于节点 ID 的语义差异比较，保留字段级
  修改证据，过滤画布布局噪声，并对未知 `properties` 配置保守比较。
- 使用迭代 Kosaraju 识别强连通分量、Kahn 算法生成拓扑层；明确子图、
  旁路与自定义运行时行为的覆盖边界。
- 构建 React 可视化诊断台和单文件离线发行版，设计恶意输入边界、PNG
  CRC/解压预算及输出转义；以单元测试、浏览器测试和 CI 保障质量。

这些描述应在理解和能够讲解实现后使用；不添加未经实测的用户量、收入、
性能提升百分比或独立手写全部代码等表述。

## 两分钟演示

1. 打开便携 HTML，展示无安装、无服务器的工作台。
2. 选择故障示例，点击断线诊断定位节点，说明错误来自具体图结构证据。
3. 恢复正常示例并打开版本对比，解释参数变化与布局移动的区别。
4. 导入 PNG 示例，展示无需解析图像像素即可恢复工作流。
5. 导出报告，展示 CLI 与前端共享同一核心。

## 面试讨论点

- 为什么 API prompt 与 UI workflow 不能直接逐字段比较？
- 为什么未知节点不能直接被判为缺失插件？
- 图中有环时，如何避免递归栈溢出并保持可读布局？
- 为什么 SCC/Kahn 遍历是 `O(V + E)`，完整导入和语义 diff 却不能笼统称为线性？
- 为什么 `properties` 的配置变化值得保留，却不能直接推断生成结果变化？
- 如何限制 PNG 解压后的内存占用，而不只检查压缩文件大小？
- 为什么采用稳定节点 ID 而不是猜测相似节点？
- 为什么浏览器测试需要直接打开构建后的 file:// 页面？
- 哪些能力需要运行时证据，不能由静态检查承诺？

## 可继续积累的真实贡献

以脱敏真实工作流增加兼容性 fixture；基于复现证据为 ComfyUI 文档或
上游解析器提交小型修复；在征得对方同意后收集实际使用反馈。
先形成可复现问题和测试，再扩大支持范围。
